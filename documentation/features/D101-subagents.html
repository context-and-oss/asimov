Subagents

Four Accelerate roles, each a skill that holds the method and a thin shell per harness. All read the repo's own conventions and flag instead of guessing.

Model

Scope: the Code- and Review-stage subagents: role skills, shells, and the convention overlay they share. Supersedes D101-build-subagents and D101-baley-the-code-reviewer.

§2Why

Generic AI coding help ignores the house style, and restating it costs context on every prompt.

  • Silent defaults. Where a convention is missing, the agent picks one the team never reviewed.
  • Cold first review. Style breaches and obvious defects reach the human reviewer.
  • Two harnesses. Claude Code and Codex declare agents differently; two copies of a method drift.
Audience. Developers who want code, tests and a first-pass review in the repo's own style.

§3Requirements

Functional — 9
R1
Four subagents: .NET builder, Angular builder, .NET tester, code reviewer.
R2
The whole method lives in one role-* skill on the six-field skeleton.
R3
One shell per harness: identity, model, tools, and the skill's name. Nothing else.
R4
One entry README per stack, by exact path; every @-referenced file is read.
R5
Gap: proceed on base competence and flag. Conflict: stop and flag.
R6
Every non-trivial decision cites its convention file or names its failure class.
R7
Tester and reviewer work only on the branch's diff, or an explicit target.
R8
Reviewer: two axes, Pass/Flag/Fail per finding, two tables, no verdict.
R9
A finding that depends on code outside the diff is marked uncertain.
Non-functional — 3
NF1
No product identifiers; shell models match model-choice.md (hard rules 2, 7).
NF2
The reviewer is read-only by tool budget, not only by instruction.
NF3
Skills name roles, never personas; persona names live in the shells.
Out of scope — 4
OOS1
Authoring conventions — the product repo's job.
OOS2
The reviewer fixing or approving — reviewer ≠ author.
OOS3
Roles calling one another, or auto-routing fixes — the developer routes.
OOS4
Further stacks or test types — when a primary stack needs them.
4
Business design
Principles, vocabulary, the roster, the flag rules, the decisions.

§4.1Principles

1
Reusable core, local overlay. The method ships; the conventions are read at run-time.
2
Flag, don't guess. A missing or conflicting convention is surfaced, never replaced.
3
One method, one shell per harness. The skill is the single home.
4
Review, don't fix. Evidence from the reviewer; the fix from a builder; approval from a human.

§4.2Concepts

Concept
What it means
Role skill
Role, Stack competence, Reads, Workflow, Boundaries, Output; plus Target for diff-scoped roles.

The per-harness agent file that names the persona and points at the skill.

Conventions (cites a file) or correctness & safety (names a failure class).

§4.4Rules

Rule
Fires
Does not fire
Gap
angular/ has only a naming file; the task touches state: proceed, flag.
dotnet/service-pattern.md covers it: follow and cite.
Conflict
README says "no AutoMapper"; task asks for it: stop, flag.
Task silent on mapping: the README wins.
Coverage (tester)
Branch adds one method to an untested class: flag the class, test the method.
Explicit target: the whole target is in scope.
Uncertainty (reviewer)
Diff calls an unchanged method that may return null: mark uncertain.
Bug fully visible in the hunk: Fail.
Severity (reviewer)
Pass at axis level; Flag for non-blocking; Fail for a defect or a load-bearing breach.
Never a score; never an axis omitted.

6
Technical design
Files, one run, failures, gotchas.

§6.1Platform

  • Skills: skills/role-*/SKILL.md, frontmatter name + description.
  • Claude Code shells: agents/<name>.md with model, skills: (injected at start), tools for Baley.
  • Codex shells: agents/<name>.toml, "load the skill first", model inherited.
⚠ Codex shells are a prototype. Discovery of a plugin-level agents/ folder is unverified (Q1).

§6.2A run

Entry Work Read from the repo End
  1. The shell injects the skill; builders skip the target step.
  2. Base: remote HEAD, else main, else master; an explicit target overrides; none ends the run.
  3. Output: code or tests plus a summary of citations and flags; for the reviewer, the two tables.

§6.8Known constraints & gotchas

@-lists are read, not expanded. A file read does not transclude; keep each list short.
Only the diff. Pre-existing issues in untouched files are not surfaced, by design.
Sparse Angular conventions. Frequent gap flags from Daneel are expected for now.
