Asimov run log

One text line per harness event, written by the plugin's hooks into the product repo, never by a model.

§2Why

Nothing records what Asimov did while it ran, so every feedback note is reconstructed from transcripts by hand.

§3Requirements

§4.2Hooks

Five harness events, one line each; the list is closed. Only a harness event makes a line; a hook always exits 0, never writes to chat, and writes the state file under a lock, since hooks run in parallel.

§4.3Data flow

The person The harness firing the hook The log and state files The skill and its agents, outside the log
1
Session start. Create the folder if missing, write the session line, start the state file with -.
2
Invocation. Map the skill name to a stage, take the first word as the feature, update the state, write the line.
3
Agent start. Record id, time and shell in the state; write the line.
4
Agent stop. Look up the start by id, write the line with seconds, drop the id.
5
Session end. Write the line, delete the state file.
  • A session past midnight keeps writing to the file named in its state; an agent still running at session end gets no stop line.
  • Two sessions in one repo write two files; a session resuming a build starts its own file, and the invocation line names the feature.
  • A state file a session end could not delete is swept by the next session start once it is twelve hours old.

Technical design
Platform, code map, payload mapping, failures. The data flow is §4.3; §6.5, §6.6 and §6.8 do not apply.

§6.1Platform

hooks/hooks.json at the plugin root registers one PowerShell command, hooks/scripts/asimov-log.ps1, for the five events (six registrations: a typed /asimov-* and a Skill call are two harness events), async on all but SessionEnd; the script reads the event's JSON from stdin and appends one line. The command is a pwsh … || powershell … chain, so the hook shell must be Git Bash or PowerShell 7. Codex reads the same manifest; it does not substitute ${CLAUDE_PLUGIN_ROOT} but exports it as an environment alias, which the shell expands. ASIMOV_LOG_RAW=1 adds a raw payload dump, raw-<id8>.jsonl beside the log, off by default because it carries prompt text. No escalation gate: nothing outside the log folder is written.

§9Open questions

Q1Allan Borup
SubagentStop hands over agent_transcript_path and no token field; may the hook sum tokens from that transcript, and is that worth the time it costs?
Resolution path: read the payload with ASIMOV_LOG_RAW=1 on the first run.
Q2Allan Borup
In Codex, which has no UserPromptExpansion, is a typed $asimov-plugin:… or a skill call matchable, and is agent_type present? Until then a Codex session logs no invocation line and its stage stays session.
Resolution path: the first Codex run with the hooks installed.
Q3Allan Borup
Should the feedback note become a skill that reads the log and the ledger?
Resolution path: after the first run with the log.
