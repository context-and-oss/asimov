# Research: logging Asimov runs in a product repo

Written 2026-10-07, before the design of the `.asimov/log/` artifact. Collected by a research subagent from the sources linked below; URLs accessed 2026-10-07 unless dated. Where a claim is undocumented or unverified it says so. One claim was checked against a live session transcript on 2026-10-07: in Claude Code a skill invocation is a `Skill` tool call with the skill name in `tool_input`, and a subagent spawn is an `Agent` tool call with `subagent_type`, so a hook matcher on those two tool names catches both.

Decisions taken on the basis of this note (2026-10-07, alb): the log serves traceability across stages, debugging of the toolkit and measurement of the L3 transition; it records Asimov events only, not every tool call; it is local and gitignored; it must work in Codex as well as Claude Code.

## 1. Claude Code built-in observability (what is already measured)

- **OpenTelemetry export** · opt-in via `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_METRICS_EXPORTER`/`OTEL_LOGS_EXPORTER`/`OTEL_TRACES_EXPORTER` (`otlp|console|none`; traces beta behind `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1`), standard `OTEL_EXPORTER_OTLP_*` endpoint/headers/protocol · home machine → collector, nothing in the repo · reader: ops dashboards · https://code.claude.com/docs/en/monitoring-usage
  - Metrics: `claude_code.session.count`, `lines_of_code.count`, `pull_request.count`, `commit.count`, `cost.usage` (USD), `token.usage` (`type` input/output/cacheRead/cacheCreation, `model`, `query_source` main/subagent/auxiliary, `effort`, `agent.name`, `skill.name`, `plugin.name`), `code_edit_tool.decision`, `active_time.total`.
  - Events (logs): `claude_code.user_prompt`, `assistant_response`, `tool_result` (`tool_name`, `tool_use_id`, `success`, `duration_ms`, `error_type`), `api_request` (`model`, `cost_usd`, `duration_ms`, `input/output/cache_read/cache_creation_tokens`, `request_id`, `query_source`, `effort`), `api_error`, `api_refusal`, `tool_decision`, `skill_activated` (`skill.name`, `invocation_trigger` user-slash/claude-proactive/nested-skill, `plugin.name`), `plugin_loaded`, `hook_registered`, `permission_mode_changed`, `mcp_server_connection`, `internal_error`.
  - Correlation keys: `session.id`, `prompt.id` (the same UUID hooks receive as `prompt_id`), `tool_use_id`, `request_id`, `message.uuid`, `event.sequence`. Content and real skill/agent/plugin names are redacted to `custom` unless `OTEL_LOG_TOOL_DETAILS=1`; prompt/response text needs `OTEL_LOG_USER_PROMPTS` / `OTEL_LOG_ASSISTANT_RESPONSES`; `vcs.*` repo attributes need `OTEL_METRICS_INCLUDE_REPOSITORY`.
  - Beta spans: `claude_code.interaction` → `llm_request` / `hook` / `tool` (with `agent_id`, `parent_agent_id`, `skill_name`, `subagent_type`, `gen_ai.request.model`, `gen_ai.tool.call.id`).
- **Local transcripts** · `~/.claude/projects/<cwd-encoded>/<session-id>.jsonl`, subagents under `subagents/` or `agent-<id>.jsonl`; one JSON object per message/tool-use/metadata entry; fields seen: `type` (user/assistant/system/summary/progress/file-history-snapshot/queue-operation), `uuid`, `parentUuid`, `timestamp`, `sessionId`, `cwd`, `gitBranch`, `version`, `isSidechain`, `agentId`, `requestId`, `toolUseResult`, `message.usage.{input_tokens,output_tokens,cache_creation_input_tokens,cache_read_input_tokens}`, `message.model` · home dir, 30-day sweep (`cleanupPeriodDays`) · **format declared internal; "changes between versions"** · https://code.claude.com/docs/en/sessions, https://claude-dev.tools/docs/jsonl-format (undated)
- **`claude -p --output-format json`** · result object with `session_id`, `total_cost_usd`, per-model usage, `duration_ms`, `num_turns`, `permission_denials`; `stream-json` adds `parent_tool_use_id` on subagent messages so a nesting tree can be rebuilt (`--forward-subagent-text`, v2.1.211+) and `system/init` with loaded `plugins` · https://code.claude.com/docs/en/headless
- **In-session** · `/usage` (session block: cost, API vs wall duration, lines changed, per-model tokens, prompt-cache stats; attribution by skill/subagent/plugin), `/insights` (HTML report at `~/.claude/usage-data/report.html`). `/cost` is no longer on the docs page; `/stats` is not documented · https://code.claude.com/docs/en/costs

Already measured, do not re-log: tokens, cost, model, API latency, tool success/duration, permission decisions, skill activations. Not available anywhere by default: feature/stage identity, which files a run touched as a set, attempt counts, outcomes (pass/fail/stop), human rulings.

## 2. Claude Code hooks

- Reference: https://code.claude.com/docs/en/hooks. Events relevant here: `SessionStart` (`source` startup/resume/clear/compact/fork, `model`), `SessionEnd` (`reason`), `UserPromptSubmit` (`prompt`), `PreToolUse`/`PostToolUse`/`PostToolUseFailure` (`tool_name`, `tool_input`, `tool_use_id`, `tool_response` on Post), `SubagentStart`/`SubagentStop` (`agent_type`, `agent_id`, `attempt`), `Stop` (`last_assistant_message`, `stop_reason`), `PreCompact`/`PostCompact` (`trigger`), `Notification` (`message`, `notification_type`), plus `UserPromptExpansion` (matcher = skill/command name), `TaskCreated/Completed`, `PostToolBatch`, `WorktreeCreate/Remove`.
- Common stdin JSON: `session_id`, `prompt_id`, `transcript_path`, `cwd`, `hook_event_name`, `permission_mode`, `effort.level`, `scratchpad_dir`, `agent_id` + `agent_type` (subagent hooks / `--agent`).
- Matchers: tool name for the tool events (`Skill`, `Agent`, `Bash|Edit`, regex `^mcp__.*`); `agent_type` for Subagent events (`^my-plugin:reviewer$`); `source`/`reason`/`trigger` for Session/Compact events. The subagent tool is `Agent`; `Task` is a legacy alias since v2.1.63 (hooks matching `Task` stopped firing) · https://github.com/k21993/hookcompat/pull/3
- Handler fields: `type` command/http/prompt/agent/mcp_tool, `async: true` (background, non-blocking), `asyncRewake`, `timeout`, `if` (permission-rule filter such as `Edit(*.ts)`), `args` exec form, `shell: powershell`.
- Plugin hooks: `hooks/hooks.json` at plugin root (`{"hooks": {...}}` wrapper), or `hooks` in `plugin.json`; merged with settings hooks. Env in the hook process: `CLAUDE_PROJECT_DIR`, `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA` (persistent per-plugin dir), `CLAUDE_ENV_FILE` (SessionStart only), `CLAUDE_EFFORT`. Worktree caveat: `CLAUDE_PROJECT_DIR` stays at the original root; use `cwd` · https://code.claude.com/docs/en/plugins-reference
- Skill/agent frontmatter may carry `hooks:` scoped to that skill/subagent (`once: true`).

## 3. OpenAI Codex

- **Hooks exist** (official): events `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop`, `Stop`, `Interrupt`. Stdin: `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `permission_mode`, `turn_id` (turn-scoped), `tool_name`, `tool_input`, `tool_response`. Config: `~/.codex/hooks.json`, `<repo>/.codex/hooks.json`, or `[hooks]` in `config.toml`; matcher is a regex on `tool_name`; `async: true` supported; **plugins can ship `hooks/hooks.json` or a `hooks` entry in `.codex-plugin/plugin.json`**, with env `PLUGIN_ROOT`/`PLUGIN_DATA` (with `CLAUDE_PLUGIN_*` aliases per `D101-codex-support.html` §6.8). Kill switch `[features] hooks = false` · https://developers.openai.com/codex/hooks → https://learn.chatgpt.com/docs/hooks; timeline SessionStart/Stop v0.115.0 (2026-03-11), PreToolUse/PostToolUse v0.117.0 (2026-03-26) · https://codex.danielvaughan.com/2026/04/15/codex-cli-hooks-complete-guide-events-policy-patterns/ (2026-04-15)
- Absent/unverified: no `prompt_id`/`agent_type` field documented; no `PostToolUseFailure`, `Notification`, `UserPromptExpansion`; **whether a skill invocation or subagent spawn surfaces as a matchable `tool_name` is not documented**.
- **Sessions** · `~/.codex/sessions/YYYY/MM/DD/rollout-<id>.jsonl` (prompts, responses, tool calls/results, approvals, token counters); `~/.codex/history.jsonl`; `~/.codex/log/codex-tui.log` (`RUST_LOG`) · home dir, no auto-cleanup · record type names not confirmed from docs; third parties call the format undocumented and unstable · https://pypi.org/project/agent-session-otel/
- **OTel** · `[otel]` in `config.toml`: `exporter = none|otlp-http|otlp-grpc`, `log_user_prompt` (default false), `environment`; events `codex.conversation_starts`, `codex.api_request`, `codex.sse_event`, `codex.user_prompt`, `codex.tool_decision`, `codex.tool_result`; a `codex.turn.token_usage` metric exists but was reported missing in `codex exec` (issue #33668). `notify` command receives `{type: "agent-turn-complete", thread-id, turn-id, input-messages, last-assistant-message, cwd}` · https://learn.chatgpt.com/docs/config-file/config-advanced

## 4. Community / vendor practice

- **disler/claude-code-hooks-mastery** · every hook event appends the full stdin payload to `logs/<event>.json` (JSON arrays, one file per event; `logs/chat.json` = copy of the latest transcript) · repo root · `logs/` **gitignored** · developer debugging · https://github.com/disler/claude-code-hooks-mastery. Sibling `claude-code-hooks-multi-agent-observability` streams the same payloads to a dashboard server.
- **claude-code-otel / ccdashboard / claude-telemetry** · OTLP → collector → Prometheus/Loki → Grafana; nothing in the repo; reads the built-in metrics of §1 · https://github.com/ColeMurray/claude-code-otel, https://github.com/NikiforovAll/ccdashboard
- **superpowers (obra)** · SDD ledger `.superpowers/sdd/<plan>/progress.md`, Markdown lines `Task N: complete (commits a..b, tests: cmd → result)`, `Task N: Ruling: …`, `Final: …` · repo, **gitignored**; reader = the executor after compaction, rulings summarised to the human. Issues #2293/#2467 show the cost of recording only finished work and of ambiguous "no commit" lines · https://github.com/obra/superpowers/blob/main/skills/executing-plans/SKILL.md
- **Beads (bd)** · `.beads/issues.jsonl` mirror of SQLite, one JSON object per issue, **committed** (later versions moved to Dolt with `.beads/` gitignored because of JSONL merge pain) · https://github.com/gastownhall/beads, discussion #2332
- **Spec Kit / OpenSpec / Conductor** · committed Markdown artifacts (`specs/…/tasks.md`, `openspec/changes/<x>/tasks.md` archived to `changes/archive/YYYY-MM-DD-<name>`, `conductor/tracks/<id>/plan.md` + `metadata.json` + `tracks.md` status) · checkbox state is the only progress record; **no run log** in any of the three · https://github.com/Fission-AI/OpenSpec, https://github.com/gemini-cli-extensions/conductor
- **Aider** · `.aider.chat.history.md` (Markdown, full prompts/replies/diffs) + `.aider.input.history` · repo root · auto-added to `.gitignore` on first run · https://aider.chat/docs/config/options.html
- **Cursor** · `~/.cursor/projects/<p>/agent-transcripts/<uuid>/<uuid>.jsonl` (+ `subagents/`), no model or token fields · home · https://github.com/Brandeling/meq/pull/2. **Agent Trace** (Cursor RFC, 2026-02-04): JSON trace record `{id, timestamp, vcs, files[ranges], conversations, contributors, tool, model}`, attribution human/AI/mixed; storage-agnostic (files, git notes, DB) · https://agent-trace.dev/, https://www.infoq.com/news/2026/02/agent-trace-cursor/
- **Copilot** · cloud agent: session log in the PR timeline, each commit message links its session; CLI: `~/.copilot/session-state/` · https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github
- **Goose** · SQLite `~/.local/share/goose/sessions/sessions.db` (JSONL before v1.10) · home · https://goose-docs.ai/docs/guides/logs/. **Devin** · hosted session URL `app.devin.ai/sessions/<id>`, linked from PRs; nothing in-repo · https://docs.devin.ai/work-with-devin/devin-review
- **Gemini CLI** · OTel to a local file: `telemetry.outfile` / `GEMINI_TELEMETRY_OUTFILE`, events `gemini_cli.user_prompt|tool_call|api_request|api_response`, `logPrompts` default true · https://geminicli.com/docs/cli/telemetry/
- Cross-tool survey: six CLIs all log to the home dir; only Claude Code sweeps; only Claude Code and pi document the format · https://allaboutcoding.ghinda.com/where-ai-coding-clis-store-session-logs/ (2026-08)

## 5. Standards for the schema

- **OTel GenAI semconv** (stability *Development*): spans `invoke_agent {gen_ai.agent.name}` (`gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.agent.name|id`, `gen_ai.conversation.id`, `gen_ai.request.model`, `gen_ai.usage.input_tokens|output_tokens`, `gen_ai.usage.cache_read.input_tokens`, `gen_ai.response.finish_reasons`, `error.type`), `invoke_workflow {gen_ai.workflow.name}` for multi-agent processes, `execute_tool {gen_ai.tool.name}` (`gen_ai.tool.call.id`, `gen_ai.tool.type`, opt-in `gen_ai.tool.call.arguments|result`); tool spans are siblings of the chat span, not children · https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md, …/gen-ai-spans.md
- **OpenInference** · `openinference.span.kind` ∈ LLM/TOOL/AGENT/CHAIN/…, `llm.model_name`, `llm.token_count.prompt|completion` · Arize-specific; OTel GenAI is the vendor-neutral choice · https://arize-ai.github.io/openinference/spec/semantic_conventions.html
- **CloudEvents 1.0.2** · envelope `specversion`, `id`, `source`, `type`, optional `subject`, `time`, `datacontenttype`, `data` · https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md
- **W3C PROV-DM** · Entity / Activity / Agent with `used`, `wasGeneratedBy`, `wasAssociatedWith`, `wasAttributedTo`; PROV-JSON serialisation · https://www.w3.org/TR/prov-dm/ (2013-04-30), https://prov.readthedocs.io/en/3.2.2/explanation/prov-dm.html
- **OTLP JSON file** · collector `fileexporter` writes one OTLP JSON record per line (`.jsonl`), rotation by `max_megabytes`/`max_days`/`max_backups`; `otlpjsonfilereceiver` reads it back · https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/exporter/fileexporter/README.md

## 6. Committed vs gitignored; per-run vs append-only

- Committed as evidence: Beads `issues.jsonl` (then abandoned for merge reasons); OpenSpec/Conductor/Spec Kit task files; superpowers' own ledger is gitignored but its *commits* are the evidence; Copilot/Devin/Entire put the evidence *behind a link* in the commit or PR (Entire: "every commit an agent makes becomes a checkpoint: the code change paired with the prompt, reasoning, and tool calls", secrets redacted; storage mechanism **not verified**) · https://docs.entire.io/; Agent Trace leaves storage open and names git notes as one option.
- Gitignored by convention: Aider history, disler `logs/`, every vendor transcript (home dir). Reason given each time: prompts, outputs and possibly secrets.
- File strategy: vendors use one file per session (Claude, Codex, Cursor); the collector rotates by size/age; disler appends per event type; Beads' single append-only JSONL in git produced merge conflicts across branches.

## Implications for Asimov

1. Log **run semantics, not telemetry**: feature slug, stage, skill, S101/S102 ids, phase, attempt, outcome, files owned, human ruling. Tokens/cost/model/latency are already in OTel, `/usage` and `--output-format json`; carry only the join keys (`session_id`, `prompt_id`, `tool_use_id`, `agent_id`) so a reader can cross to them.
2. Hooks can fill both harnesses: Claude Code `hooks/hooks.json` in the plugin (`PreToolUse` matcher `Skill`, `SubagentStart|Stop`, `PostToolUse` matcher `Agent`, `SessionStart|End`, `Stop`, async) and Codex `hooks/hooks.json` in the same plugin (`PreToolUse|PostToolUse|SubagentStart|SubagentStop|Stop|SessionStart|SessionEnd`), but with different env (`CLAUDE_PLUGIN_ROOT` vs `PLUGIN_ROOT`) and without `prompt_id`/`agent_type` on Codex; whether a Codex skill call is matchable is unverified, so the asimov-skills must also write their own stage events.
3. Use `cwd` from the hook payload, not `CLAUDE_PROJECT_DIR`, so worktrees log into the right repo.
4. Two policies are the field's norm: a redacted run record per feature and a raw debug log; one file per run avoids the Beads merge problem if a log is ever committed. (Asimov decided 2026-10-07 on local, gitignored only; the per-run split still matters for readability.)
5. Prompt and tool text stay out of the log; link to `transcript_path` and the session id instead (every vendor redacts by default; Copilot/Devin/Entire link rather than inline).
6. Field names from OTel GenAI where they exist (`gen_ai.agent.name`, `gen_ai.tool.name`, `gen_ai.tool.call.id`, `gen_ai.request.model`, `gen_ai.usage.*`, `gen_ai.conversation.id`, `error.type`), a CloudEvents envelope (`id`, `source`, `type`, `subject`, `time`, `data`) per line, and `asimov.*` for stage/feature/task/attempt/outcome; all conventions are still *Development*, so pin the version in the file header.
7. For traceability a PROV reading fits the ledger already in place: activity = skill run, agent = subagent/person, entity = D101/S101/S102/commit; the log line is the `used`/`wasGeneratedBy` edge the ledger does not record.
8. Record in-flight state (`started`) as well as `done`, and an explicit `commits: none`; superpowers' issues show both gaps break resume and audit.
9. Measurement per stage needs wall time and attempt counts from the log joined to tokens from OTel/`--output-format json` by `session_id`; without `OTEL_LOG_TOOL_DETAILS=1` skill and agent names arrive as `custom`, so the log must carry them itself.
10. Codex lacks `PostToolUseFailure`, `Notification` and per-agent ids; expect sparser Codex logs and mark the harness on every line.
