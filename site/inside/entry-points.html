Entry points

Five skills a run starts from, in Claude Code, Codex or OpenCode.

Name one, or just say what you want: in a repo with asimov.md, the words of your message start the right one. Each carries the conversation of one run and reads its method from the plugin at run time, so nothing is copied into your repo to drift.

Entry pointStageWhat a run does
asimov-initSetupShows a write plan, then writes the asimov.md marker, the Codex agent shells, a convention read-list per stack, the project info and the docs site. Touches neither CLAUDE.md nor AGENTS.md.
asimov-designDesignInterview → D101 as HTML. Stops after the business design; run again for the technical design. Say review for the gap check and the persona reads: no edit, no verdict. Say architecture for the area's D100.
asimov-specSpecReads a full-design D101, or an approved ticket, with the architecture and the repo. Questions in one message, then the whole plan in one file, checked by a script before you see the cut. Your go approves it and renders one task spec per task.
asimov-buildBuildBuilds an approved plan phase by phase on a feature branch: each task to the agent its role names, Baley reviews, Powell runs every check, the phase is committed. No gate inside the build; a stop proposes what to do, and the next run takes it. Never a pull request.
asimov-projectThe frameKeeps the engagement's pages under project/: the risk log first. Not a stage, kept while the stages run.
  • An entry point asks before it writes. It asks for what the artifact needs and stops when the artifact's own bar says so.
  • A review never edits. Findings go to you; the verdict stays a person's.
  • You decide between stages, never inside one. The signed design, the plan's go, the pull request.
  • Each tells you how mature its artifact is before its first question, when the level is below adopt. See Maturity.
  • Not an entry point: artifact-persona-authoring, tool-deck-authoring and the personas are plain skills you ask for. See Skills.
