Commands

What you type, in Claude Code or Codex.

Each one reads the repo's definitions and conventions at run time. There is no copy inside the plugin to drift. The same name works in both tools: /asimov-spec in Claude Code is $asimov-plugin:asimov-spec in Codex, one file underneath.

CommandStageWhat it does
/asimov-initSetupWrites asimov.md, imports it from CLAUDE.md, scaffolds convention read-lists, generates the docs landing page. Claude Code only; in Codex, codex-asimov-init does the same into an AGENTS.md region.
/asimov-designDesignInterview → D101 as HTML. Stops after the business design; run again for the technical design. Name a legacy markdown D101 and it renders it to HTML instead.
/asimov-design-reviewDesignGap check against the bar plus persona reads. Never edits, never approves.
artifact-persona-authoringDesignShows the persona roster, then interview → a custom persona skill in your repo.
/asimov-specSpecReads a full-design D101, or an approved ticket, and the repo. At most five questions, then the cut as a plan view; on your go, one task spec per task, each checked blind, then the plan as a whole.
/asimov-spec-validateSpecShows the plan view, runs the blind check on every task spec and the plan checks. Writes nothing but a gitignored sidecar. The author's preview and the reviewer's first read.
  • A command interviews before it writes. It asks for what the artifact needs and stops when the artifact's own bar says so.
  • A command that reviews never edits. Findings go to you; the verdict stays a person's.
  • Every command tells you how mature its artifact is before its first question, when the level is below adopt. See Maturity.
