Skills

The method, shared by every tool.

A skill is one file, SKILL.md, that holds one procedure: how to cut a plan, how to review a design as a given reader, how a .NET builder works. Claude Code and Codex read the same file. So do you, when you do the step by hand. Nothing above a skill carries a method: a command composes skills, an agent is a shell around one.

  • One home per method. A procedure lives in one skill. The command that uses it names it and never restates it, so a hand edit and a run follow the same rules.
  • Two levels, never three. An asimov-skill calls skills and carries no method. A skill reads artifacts and calls no skill.
  • Same file in both tools. What you type is /asimov-spec in Claude Code and $asimov-plugin:asimov-spec in Codex; the file underneath is one. Codex ignores the model a skill pins and runs the session's.
  • Reads by path, never a copy. A skill reads the definition, the template and the contract from the plugin, and your conventions from your repo. There is no copy to drift.
  • Yours live in your repo. A custom persona is a skill under .claude/skills/persona-<slug>/. The plugin ships the form and the standard readers; the concrete reader stays yours.

A skill is an authored file, not a running service. Walk away and you keep the method.
