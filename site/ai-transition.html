AI transition

How to think about AI in software delivery.

AI is changing what it means to build and deliver software. Two concepts make it possible to talk about it precisely, inside a team and with its customer:

  • Levels (L0–L5) — where a developer operates on the human-to-agent spectrum.
  • Zones (Z1–Z3) — how deeply AI is integrated into a given engagement.

Together they scope a project, frame risk and value, and settle what "using AI" actually means in a given context.

Part 1 · Individual maturity

Levels

Six steps of AI autonomy — L0 to L5 — adapted from SAE autonomous driving levels. Each level changes not just who does the work, but what the work is. The shift isn't gradual at L3: a new layer appears between design and code.

L0No AI L1Autocomplete L2Copilot L3Agent (HIL) L4Autonomous L5Full Auto
Pipeline key Human does it Human + AI together AI does it New step (didn't exist before)
L0 No AI Traditional · Software 1.0
"We write the code."
Requirements→ Design→ Code→ Review→ Test→ Deploy→ Observe

Knowledge lives in people's heads. Design-to-code happens through implicit understanding — hallway conversations, tribal knowledge, "you know what I mean."

Lead time weeks Role Maker Risk Bus factor, knowledge silos
L1 Autocomplete "Spicy autocomplete" · Cursor Era 1
"AI finishes my sentences."
Requirements→ Design→ Code (Dev + Tab)→ Review→ Test→ Deploy→ Observe

Same process, faster typing. AI predicts the next line from context clues. No process change — just a faster keyboard. Same team, same roles, same decisions.

Lead time days Role Maker (faster) Risk Accepting wrong suggestions without reading
L2 AI Copilot AI-Assisted · Pair programmer · Cursor Era 2
"AI is my pair programmer."
Requirements→ Design→ Code (Dev + AI)→ Review (+ AI flags)→ Test (+ AI gen)→ Deploy→ Observe

AI becomes interactive — generates whole functions, writes tests, explains code. But the human drives every decision. AI infers intent from code patterns. This is where most teams are today. The ceiling: AI guesses, sometimes wrong.

Lead time hours–days Role Maker who reviews AI Risk More code than humans can review
L3 Agentic — Human in the Loop Conditional autonomy · Agent mode · AI-Native
"AI builds it. I approve."
Intent→ Design→ Spec→ Code→ Review vs. Spec→ Test vs. Spec→ Approve→ Deploy→ Observe

Where Asimov sits. Asimov tools Design, Spec, Code, Review and Test today; Approve is the human gate.

The spec layer appears. What was implicit knowledge in your head must become an explicit written artifact — agents can't read minds. The spec IS the product; code is the output. This is the sensible default for production.

Lead time minutes–hours Role Director / Reviewer Risk Rubber-stamping → high change fail rate
L4 Agentic — Autonomous High autonomy · "Developer as PM" · Cursor Era 3
"Write a spec, walk away, check if tests pass."
Intent→ Spec (AI drafts, human reviews)→ Build + Test→ Self-Review→ Audit (spot-check)→ Deploy + Observe→ Report

AI generates specs from intent, then implements autonomously. Human shifts from reviewing code to reviewing outcomes. Multi-agent collaboration: planner, builder, tester, reviewer. Implementation is a black box — you check if tests pass, not how code looks.

Lead time seconds (internal) Role Specifier / Auditor Risk Silent failures, strategic drift
L5 Fully Autonomous "Dark Factory" · Software 3.0
"AI runs the show. Humans set the direction."
Vision→ Everything (agent fleet)→ Self-Heal→ Report→ Escalate (if stuck)

End-to-end autonomous pipeline: spec, build, test, ship, operate, heal. Human provides vision, values, and constraints — not instructions. Largely theoretical today; IDC estimates <5% of organisations will reach this by 2026.

Lead time continuous Role Strategist Risk Nobody understands the system
The big shift at L3

A specification layer appears

At L0–L2 AI helps a human write code. At L3+, a human writes a spec and the agent writes the code. The total thinking doesn't decrease — it shifts from how to build to how to describe.

L0–L2 — Documentation describes

Source code, tests, and pipelines are the output. Design docs, READMEs, and API docs are decorative — they describe the system after it's built and drift out of date.

L3+ — Specification drives

Functional specs (what it does), technical specs with ADRs (how & why), quality specs (acceptance criteria), and constraints (CLAUDE.md) become first-class artifacts — checked into source control, schema-validated, machine-readable. They drive the agent, verified automatically.

The paradox

To make AI do more work, humans must do more upfront work.

The total thinking doesn't decrease. The typing shifts from code to specification. The skill shifts from "how to build" to "how to describe."

Karpathy: Software 1.0 (code) → 2.0 (weights) → 3.0 (prompts). The programming medium changes.

Part 2 · Project & customer depth

Zones

Three zones — Z1 to Z3 — describing how deeply AI is integrated into a customer engagement. Each zone carries different implications for agreement, risk, and value.

Z1 Embedded AI

AI is built into the tools your team uses every day. This is not a choice — it's the default. Local and enterprise AI covered by standard licenses and DPAs; opt-out is partial and every update adds more AI.

VS Code / Rider / VS 2026IntelliSense, AI completions, refactoring
GitHubAI search, PR summaries, vulnerability detection
Jira / ConfluenceAtlassian Intelligence, summaries, search
Microsoft 365Copilot in Word, Excel, Teams, Outlook
Slack / TeamsAI summaries, smart search, replies
Windows / macOSOS-level Copilot / Intelligence
Risk Low Data Metadata, content in standard productivity tools
Z2 Intentional AI

AI moves from background feature to active tool. Someone deliberately engages AI to produce work. This is where the value is — and what needs agreement. Covers the full development process, not just code.

ActivityWhat AI does
Research & designEvaluates approaches, finds gaps in requirements, suggests architecture
Spec writingDrafts specs from requirements and design decisions
CodingWrites code from specs and context (Copilot, Claude Code)
Code reviewReviews PRs, flags issues, suggests improvements
TestingGenerates tests from specs, identifies coverage gaps
What you need
  • Agreement that AI can access codebase and project context
  • .copilotignore / .claudeignore for sensitive paths
  • No hardcoded secrets in code
  • Human review on all AI-assisted output
  • Enterprise-grade tools only (DPAs, no-training clauses)
Risk Medium Data Code + project context shared with provider
Z3 Data & Environment Access

AI touches real data — not code, but what the code processes. This is where GDPR, data residency, and real security concerns kick in. Most projects don't need this; 90% of AI value comes from Zone 2 without touching real data.

WhatExamples
Business dataProduct catalogs, pricing, configurations
Database accessAI running queries against real data
EnvironmentsAI connecting to staging or production
LogsProduction logs (may contain PII)
Personal dataCustomer names, emails, user behavior
Risk High Needs GDPR tooling, data residency, dedicated credentials, audit logs
How the axes meet

Levels × Zones

The two dimensions compose. Saying "L3 on Zone 2" is precise: a developer operating at agent level with human oversight, on an engagement with intentional AI integration. Not every combination is meaningful — higher Levels require a Zone deep enough to support them.

Asimov is built for L3 on Zone 2: agent level with human oversight, on code and project context, never on real data.

At a glance

Summary

  • L0–L5 = individual maturity on the AI autonomy spectrum
  • Z1–Z3 = depth of AI integration in an engagement
  • L3 introduces the specification layer — specs drive the agent
  • Z2 is where intentional AI value kicks in — with agreement
  • Z3 adds real data access — separate GDPR/security scope
  • Shared language = alignment across employees, projects, customers
