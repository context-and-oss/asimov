Read by
The builder it is written for, as its whole brief. The reviewer, as part of the plan. The build run, when it verifies the code against it.

What it holds

  • A header copied from the plan: role, tier, dependencies, traces. The brief stands alone; the plan check confirms they still match.
  • Intent, in the design's words, traced to the requirement it serves.
  • Files it creates, modifies and tests. Exact paths; also the set it owns. Nothing else is touched.
  • Interfaces it consumes and produces, by exact signature, so neighbouring tasks agree before either exists.
  • Behaviour as Gherkin scenarios, one per behaviour, every rule with its counter-example.
  • Constraints specific to this task: musts, must nots, preferences, escalation triggers. The global ones are inherited, never repeated.
  • Steps, test first, one action each, with the code inline where the task is transcription.
  • Acceptance criteria each checkable by running something, and out of scope, one line each.

The bar

Buildable blind. A competent builder with no conversation history, only the repo, the D101 and this file, builds it and knows when it is done. No placeholders. The builder never edits what it does not own; a conflict is a stop and a report, not a fix.

Validated blind

The model that wrote the spec has the conversation in its head and fills the gaps from memory. So a fresh reader checks it instead.

  • Write, then check. Each task spec goes to a fresh read-only subagent as soon as it is written. The report is one row per check, no verdict.
  • Fail, then rewrite. A failed check sends the spec back; the rewrite is checked again.
  • Three fails, or a design gap, stop the run. A spec that fails three times, or a finding that points at the D101 rather than the spec, is reported, not rewritten. The design is fixed first.

Rules

  • No placeholders. No TBD, no handle edge cases, no similar to task 3. A step the author cannot write is reported, not papered over.
  • Code to write is inline; code that exists is linked. Never a pasted enum or schema.
  • Own your files; stop at the edge. Needing a file outside the owned set is an escalation, not a judgement call.
  • Inherit, don't repeat. Global constraints and the escalation route live in the plan.

Never without a plan

A bug fix from the board skips the design document, not the plan. Its approved ticket is the design, and its plan may have one task; the task then traces to the ids the plan gave the ticket's items.
